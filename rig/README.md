# Timeline rig assets

Generated by `generate_sheets.py`. Reprint with e.g.
`python generate_sheets.py --duration 60 --speakers 3 --bands 3`.

The 60 s timeline is **folded across `--bands` rows** (default 3 × 20 s) so each
second gets ~3× the width of one 60 s axis — finer, easier boundary placement.
A token's **row picks the time band**, its x picks the time within it; global
time = `band.t0 + (x - x0) / band.mm_per_s`. Speakers are carried by the
**tokens** (id + colour), not the rows.

## Files
- `timeline_a3.pdf` — print on **A3**, at **100% / Actual size**.
- `tokens.pdf` — print on **A4**, at **100% / Actual size**.
- `mapping_constants.txt` — developer constants (see below).

## Marker scheme (all DICT_4X4_50)
- IDs 0,1,2,3 = corner fiducials, TL,TR,BR,BL. Frame reference for the homography.
- IDs 10+ = speaker tokens (S1=10, S2=11, S3=12, ...).
- IDs 20+ = boundary-handle tokens (B1=20, ...).
- ID 30  = playback token (transport: STOP/PLAY/PAUSE boxes + SEEK strip).
The three ranges are disjoint so the tracker separates fixed sheet-reference markers,
speaker tokens, and boundary handles by ID alone.

## Operations (problem-1 disambiguation: by marker ID)
- Speaker token dropped at a segment's time (in any band row) -> reassign that
  segment to the speaker. The token's ID carries the speaker; the row carries the
  time band, not the speaker.
- Boundary handle at a time -> snaps to the nearest segment edge; sliding it moves
  that boundary. Speaker tokens never move boundaries, so the two operations never
  share a gesture.
- Playback token in a STOP/PLAY/PAUSE box -> that transport action; on the SEEK strip
  -> jump playback to that time. The SEEK strip is a single 60 s axis (seeking needs
  no precision). `generate_sheets.py` writes `transport_zones.json` (band geometry +
  transport zone rectangles in sheet-mm) which `tangible_input.py` reads.
  Playback is tangible-only; its timing is logged so analysis subtracts it (see app/).

## Mapping (camera -> sheet -> time)
The tracker computes a homography from the 4 corner marker centres, maps a token
centroid to sheet-mm, then uses the **band geometry** in `transport_zones.json`:
the row (y) selects the band, and `t = band.t0 + (x - band.x0) / band.mm_per_s`.
- 3 × 20 s bands over a ~360 mm axis => **18 mm/s, 1 mm ≈ 55 ms** (vs 167 ms on a
  single 60 s axis). Well inside the 0.15 s "corrected" boundary tolerance.
- The SEEK strip stays a 60 s axis at 6 mm/s (`mm_per_second` in the JSON).

## Printing
- Matte paper. If laminating, matte laminate only (glossy blows out marker corners).
- After printing, measure the 50 mm bar on the A3 sheet to confirm scale.
